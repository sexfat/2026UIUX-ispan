Unit 09

RWD 概念

什麼是響應式網頁？

同一套設計稿與同一套 CSS，在不同裝置的螢幕寬度下自動調整版面配置，不需要另外做一套。

手機：單欄，全部垂直堆疊

平板：主欄 + 一個側欄

桌機：三欄 + 頁尾

RWD（Responsive Web Design）指的就是這件事：內容在不同 viewport 下能流動、調整或重新排列，讓每個裝置都拿到一致的好體驗——不是三份設計稿，是一份設計稿的三種排法。

版面設計模式

RWD 五種設計模式

網頁內容在不同 viewport 下有五種常見的流動方式，先認得出來，之後才挑得對。

模式怎麼變化示範
Mostly Fluid
局部流動		寬螢幕側邊加留白，縮小時欄位逐步垂直堆疊查看 ↗
Column Drop
欄位下移		螢幕縮小時，最右側欄位依序移到下方查看 ↗
Layout Shifter
區塊轉換		不同尺寸下整體區塊的位置與順序大幅改變查看 ↗
Tiny Tweaks
細微調整		版面結構不變，只微調字級、間距與圖片尺寸查看 ↗
Off Canvas
超出畫布		次要內容（如側邊欄）預設藏在畫布外，手動觸發才顯示查看 ↗
五種不互斥，同一個網站常常混用——導覽用 Off Canvas，內容區用 Mostly Fluid。

斷點設置規劃

先知道使用者用什麼裝置，再決定斷點

斷點是版面切換的臨界寬度，常見的四個區間如下——但這只是起點，不是規定。

手機≤ 640px
平板641–1024px
桌機1025–1440px
寬螢幕1441px 以上
舊網站改版：查 Google Analytics 的裝置分佈，依主要裝置決定優先順序。全新網站：用 StatCounter ↗ 查同類型網站的市場數據再選斷點。

Unit 09

斷點設置策略

行動優先 vs 桌機優先

兩種思路都是從一端往另一端做，差別在起點跟 Media Query 怎麼寫。

Desktop First：桌機 → 平板 → 手機，Media Query 用 max-width。Mobile First：手機 → 平板 → 桌機，用 min-width。多數團隊兩端都會看過，但 Mobile First 的空間限制通常逼出更精準的決策。

表格設置規劃

響應式表格的四種策略

表格在小螢幕最難處理，要依資料性質選對應方案，不是每次都水平捲動了事。

策略做法
隱藏欄位小螢幕隱藏次要欄位，只留核心資訊。適合欄位有明顯主次之分的表
水平捲動保持完整 Table 結構，讓容器可左右滑動，資料不刪減
CSS／DIV 排版把 Table 結構轉成 Flexbox／Grid，自己控制每格的排版與尺寸
破壞表格排版行動端把每一列重排成獨立卡片，欄名用 data attribute 附加
實作前先問：這張表的欄位有沒有明顯主次？沒有主次的表，隱藏欄位這條路就不能走。綜合參考：elvery.net/demo/responsive-tables ↗

Unit 09

響應式圖片規劃

圖片在各裝置的處理方式

圖片是網頁最重的資源，處理不好，行動網路的使用者第一個放棄等待。

做法解決什麼
圖片裁切用 <picture> 依裝置顯示不同焦點的裁切版本，手機看特寫、桌機看全圖
等比縮小設 max-width: 100%，圖片隨容器自動縮放，不超出邊界
減少請求數合併圖檔、改用 CSS Sprite 或 SVG Icon，降低 HTTP request
背景圖換圖用 Media Query 在不同斷點切換背景圖，手機不用下載不必要的大圖
背景圖裁切background-size: cover 配 background-position 控制焦點
整張換圖不同斷點用完全不同的圖（橫幅 vs 直幅），構圖跟著改
最基礎、最該先做的是「等比縮小」——一行 CSS 就能解決圖片爆版的問題。

概念比較

RWD 響應式 vs AWD 自適應

兩者最後看起來都像「會變」，但背後的技術機制完全不同。

比較RWD 響應式AWD 自適應
運作方式同一套 CSS，依 viewport 流動調整偵測裝置類型，載入對應版本
版面切換平滑漸進，沒有跳動感需要切換時間，可能閃一下
維護成本單一版本，維護簡單多套版本，成本較高
客製化程度較難針對特定裝置大幅客製可為每個裝置做最佳化體驗
適用情境大多數網站的首選對效能要求極高的大型產品
實例可以自己比：PChome（RWD）↗ 與 momo（AWD）↗ 用手機跟桌機各開一次，感受載入行為的差異。現在大部分網站用 RWD 搭配 CSS Grid／Flexbox + Media Query 就能應付。

核心概念 · Flow

流動性（Flow）

內容隨螢幕縮小而自然垂直堆疊，這是 CSS 的預設行為，也是 RWD 能成立的基礎。

左邊 Flow：螢幕變窄時，下面的元素自動被推下去，依序排列。右邊 Static：用固定 px 定位，小螢幕會超出邊界或互相重疊。會用相對單位做流動排版，是 RWD 的第一課。

核心概念 · Units

相對單位與靜態單位

知道 % 和 px 各自的使用時機，是寫好 RWD 的基本功。

相對單位（%、vw、vh、em、rem）：寬度隨螢幕或父元素縮放。靜態單位（px、pt）：寬度固定，適合 icon 大小、按鈕最小點擊區域這類不該縮放的元素。常見寫法：width: 100%; max-width: 1200px——填滿螢幕但不超過版心寬度。

核心概念 · Breakpoints

斷點設計（Breakpoints）

什麼時候該切換版面、什麼時候讓它自己流動，是兩種不同的處理方式。

斷點不該照裝置尺寸表去設。正確做法是：把瀏覽器慢慢縮小，版面「開始看起來奇怪」的那個寬度，就是斷點該放的地方——讓內容決定斷點，而不是讓 iPhone 的型號決定斷點。

核心概念 · Components

組件寫法（Nested Components）

善用容器包裝，響應式元件才好控制、好維護。

用一個 wrapper 容器包住相關元素，容器設 position: relative，子元素相對容器定位，不會被整體版面牽著跑。原則沒變：icon、按鈕最小點擊區域用 px；欄寬、圖片最大寬度、全幅 banner 用 %。

字型與圖示選用

系統字型 vs 網頁字體／點陣圖 vs 向量圖

設計稿裡兩個常被忽略、卻直接影響跨裝置顯示品質的細節。

系統字型Windows、Mac、iOS、Android 預設字型都不同，跨平台顯示不一致
網頁字體用 Google Fonts 等 CDN 字型，所有裝置下載同一套；行動網路要注意字重數量與載入速度
點陣圖解析度固定，放大會糊，在高密度螢幕上 icon 不清晰
SVG 向量圖任意縮放不失真，檔案通常更小，介面 icon／Logo 優先選它

Figma 應用

在 Figma 設計多裝置版本

用 Constraints 與 Auto Layout 讓設計稿本身就反映響應式邏輯，不用另外寫說明文件。

Step 01 · 建立多個 Frame分別建 Mobile（375px）、Tablet（768px）、Desktop（1440px）三個 Frame，對應不同斷點
Step 02 · 設定 Constraints每個元素設 Left／Right／Scale，讓它在 Frame 縮放時保持相對位置關係
Step 03 · 使用 Auto Layout建流動元件，設定 Fill／Hug／Fixed 控制每個元素的縮放行為
設計師的責任：在 Figma 裡清楚標示「這個元件在手機版怎麼變」，工程師才能照著實作對。多 Frame 設計是設計師跟工程師溝通響應式邏輯最直接的媒介。

本堂小結

RWD 不只是「縮小版面」

而是從一開始就用「多裝置」的思維規劃設計。

  • 五種版面模式：Mostly Fluid、Column Drop、Layout Shifter、Tiny Tweaks、Off Canvas
  • 斷點策略：讓內容決定斷點，而不是裝置型號決定斷點
  • 用相對單位（%）搭配 max-width 控制版面流動
  • 表格、圖片、字型、圖示各有對應的響應式處理策略
  • Figma 的多 Frame + Constraints + Auto Layout 是設計端的響應式工具
