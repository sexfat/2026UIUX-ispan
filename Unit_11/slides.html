APP UI 設計規範
Units

Logical size vs. physical pixels

設計尺寸描述「看起來多大」
像素描述「螢幕如何顯示」

邏輯單位

iOS 使用 pt；Android 使用 dp 與 sp。介面在不同密度裝置上維持接近的視覺大小。

物理像素

px 是螢幕上的實際像素。高密度螢幕以更多像素呈現同一個邏輯尺寸。

logical size × density scale = physical pixels
APP UI 設計規範
iOS Units

Point-based layout

iOS 介面以 pt 設計，圖像資源依倍率輸出

1 pt介面配置使用的邏輯單位，不等於固定數量的實體像素。
@2x1 pt 對應 2 × 2 px 的像素區域。
@3x1 pt 對應 3 × 3 px 的像素區域。

Figma 畫布中的數值可視為邏輯尺寸；點陣圖輸出才需要考慮 @2x、@3x。

APP UI 設計規範
Canvas

Adaptive canvas

畫布是設計基準，不是唯一裝置答案

檢查面向主要基準補充驗證
一般手機以專題目標裝置或主流尺寸建立主要稿不同寬度下的內容伸縮與對齊
較小畫面最長文字、鍵盤展開、底部操作區內容截斷、按鈕擠壓與捲動範圍
較大畫面內容寬度、空白與分欄策略平板或可調整視窗的版面變化

Auto Layout、Constraints 與 responsive resizing 讓同一套介面規則適應尺寸變化。

APP UI 設計規範
Safe Area

System-defined insets

Safe Area 保留內容與系統功能的可操作空間

  • 頂部邊距 47–59pt：相機區、Dynamic Island 與圓角不遮住重要資訊
  • 底部邊距 34pt：Home Indicator 和系統手勢不與主要操作衝突
  • 左右邊距 16pt：內容與螢幕邊緣維持可讀與可點擊的間距
  • 系統列、鍵盤與工具列出現時仍維持清楚層級

Android Units

Density-independent sizing

Android：版面使用 dp，文字使用 sp

DP · Density-independent Pixel

按鈕、圖示、邊距與版面尺寸。以 160 dpi 為基準，1 dp 約等於 1 px。

SP · Scalable Pixel

文字與行高。除了裝置密度，也會回應系統字體大小偏好。

16sp body text · 24dp icon · 48dp touch target
APP UI 設計規範
Android Density

Density buckets

dp 維持尺寸，密度資源維持清晰度

mdpi基準密度 1×
xhdpi2× 點陣資源
xxhdpi3× 點陣資源

向量圖示可跨密度縮放；照片與其他點陣圖仍需要適合的解析度與裁切策略。

完整資源桶另包含 hdpi 1.5× 與 xxxhdpi 4×。

APP UI 設計規範
Forms

Keyboard-aware layout

表單不是靜態欄位，而是一組輸入狀態

輸入前

標籤、格式線索、必填資訊與適合的鍵盤類型。

輸入中

焦點清楚，欄位不被鍵盤遮住，下一步仍可到達。

驗證後

錯誤位置、原因與修正方向靠近對應欄位。

內容上移、鍵盤收合、返回行為與未儲存內容，都屬於表單流程的一部分。

APP UI 設計規範
Gestures

Discoverability

手勢可以加速操作，不適合作為唯一入口

Swipe to delete

滑動可快速刪除；更多選單或明確按鈕提供可發現的替代入口。

Edge back gesture

返回手勢符合平台慣例；畫面仍保留清楚的層級與離開結果。

重要操作同時具備視覺線索、觸覺／動畫回饋與可復原機制。

APP UI 設計規範
Accessibility

Perceivable · operable · understandable · robust

無障礙不是最後加上的檢查項

對比

一般文字至少 4.5:1；大型文字與必要圖示、控制邊界至少 3:1。

語意

可存取名稱、角色、閱讀順序與狀態變化能由輔助技術取得。

操作

觸控目標、手勢替代方式、字體縮放與橫豎向變化可用。

APCA 可作為感知對比的延伸觀察；現行交付仍以 WCAG 2.2 檢核為基準。
