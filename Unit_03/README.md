# 單元 3：用戶研究 ①：競品分析與 Persona
> 對應資展時段：2026/07/08（三）09:00–16:30

## 單元目標

- 理解競品分析不是抄襲介面，而是用結構化觀察建立市場理解、使用者期待與設計決策依據。
- 能選出 3–5 個直接競品、間接競品與參考性產品，並說明選擇理由。
- 能依專題目標設定分析維度，從功能、任務流程、資訊架構、UI、使用情緒與商業模式整理競品差異。
- 能把表格觀察收斂成 1 頁洞察，提出設計機會與取捨。
- 能把競品觀察銜接到 Persona，建立後續 Functional Map 與 Wireframe 的使用者基準。
- 能使用 AI 協助整理競品觀察與 Persona 假設，但清楚標註哪些仍需真實資料驗證。

## 課程介紹

本單元進入用戶研究的第一個實作主題：競品分析與 Persona。競品分析的目的不是「看到別人有什麼，我也做什麼」，而是看懂使用者目前有哪些選擇、主流產品如何安排功能與流程、哪些設計已成為市場期待、哪些地方仍存在未被滿足的需求。

競品分析能幫助設計師建立設計決策依據。當你能指出「多數產品都這樣處理搜尋」、「某個註冊流程在第二步容易流失」、「某族群在既有產品中沒有被照顧」時，後續提案就不只是個人喜好，而是有觀察、比較與取捨邏輯支撐。

Persona 會接在競品分析之後。它不是「25 歲上班族」這種人口統計標籤，而是把使用者的目標、心智模型、使用情境、痛點與期待整理成可被團隊討論的決策模型。好的 Persona 能回答：「這位使用者在這個情境下最不能忍受什麼？他為什麼會選擇或放棄某個功能？」

AI 在本單元中扮演輔助角色：可以協助產生分析表欄位、整理評價文字、歸納競品差異、產生 Persona 假設，但不能替代真實觀察與研究判斷。所有 AI 產出都應視為假設，需要由截圖、使用者評價、訪談或後續測試驗證。

## 課程內容

- 什麼是競品分析：功能相似、對象相近或解決相同問題的產品比較。
- 為什麼要做競品分析：
  - 了解市場現況與使用者的選擇。
  - 學習優點、避免重複錯誤。
  - 找出設計上的差異化機會。
  - 建立設計決策的依據。
  - 提升 UX 整體設計品質與敏感度。
- 競品選擇：
  - 直接競品：解決同樣問題、目標族群相近。
  - 間接競品：提供相似或替代解法，但形式或族群不同。
  - 參考性產品：不一定競爭，但在操作體驗或視覺呈現上值得借鏡。
- 常見分析維度：
  - 功能項目、任務流程、使用者情緒、資訊架構、導覽與操作性。
  - 介面與視覺、回饋與錯誤提示、差異化亮點、使用者黏著策略、商業模式支撐。
- 初學者 5 個基本維度：
  - 功能完整性。
  - 操作流程順暢度。
  - 視覺與 UI 一致性。
  - 使用情緒與體驗。
  - 設計亮點與缺點。
- 設計決策依據：
  - 市場驗證、正反案例、提案說服力、避免主觀偏誤、釐清選項與取捨。
- Persona：
  - Goals、Mental Model、Context、Pains、Gains。
  - 避免「彈性使用者」陷阱，用具體角色作為決策基準。
- AI 協作：
  - 生成競品分析表欄位、整理競品觀察、檢查洞察是否有證據。
  - 產生 Persona 假設，並標註需要真實資料驗證的部分。

## 競品類型範例

| 產品類型 | 直接競品 | 間接競品 |
|---|---|---|
| 外送訂餐 App | Uber Eats、Foodpanda | 7-11、全聯熟食、LINE 群組揪團訂餐 |
| 線上學習平台 | Hahow、Udemy、Coursera | YouTube 教學影片、Podcast、學習型 IG 帳號 |
| 線上投資平台 | 永豐金證券、凱基證券、富邦證券、口袋證券 | 財經 YouTuber、銀行理財顧問、PTT 股票討論版 |
| 約會交友 App | Tinder、派愛族、Coffee Meets Bagel、GoodNight | IG、Dcard、PTT 八卦板、Twitch 聊天 |

## 競品分析表建議欄位

| 欄位 | 觀察重點 |
|---|---|
| 產品名稱與連結 | 競品名稱、網站或 App 連結、平台 |
| 競品類型 | 直接競品、間接競品或參考性產品 |
| 目標客群 | 主要服務誰？是否與你的專題使用者重疊？ |
| 核心任務 | 使用者在這個產品中最常完成什麼任務？ |
| 核心功能 | 有哪些主要功能？功能是否完整？ |
| 任務流程 | 完成任務需要幾步？流程是否清楚、順暢？ |
| 資訊架構 | 分類、導覽、搜尋與內容組織是否合理？ |
| UI 與視覺 | 色彩、排版、圖示、易讀性、品牌一致性 |
| 回饋與錯誤提示 | 操作成功、失敗、等待、錯誤時如何提示？ |
| 使用情緒 | 哪些地方讓人安心、困惑、焦慮或驚喜？ |
| 優點 | 值得學習的做法與原因 |
| 缺點 | 使用者可能卡住或抱怨的地方 |
| 差異化機會 | 我們可以在哪個族群、情境或流程做得更好？ |
| 證據來源 | 截圖、評價、訪談、觀察紀錄或資料來源 |

## 課堂練習流程

1. 確認專題題目與核心任務。
2. 列出 3–5 個競品，至少包含直接競品與間接競品。
3. 針對每個競品完成關鍵畫面截圖與流程觀察。
4. 用 5 個基本維度完成比較表。
5. 收斂 3–5 條洞察，寫出對應的設計機會。
6. 在 FigJam / Figma 建立 1–2 位 Persona。
7. 標註哪些結論已由觀察支持，哪些只是 AI 或團隊假設。

## AI 協作提示詞

### 一、產生競品分析表欄位

```text
你是一位 UX 研究員。我正在為 [專題名稱] 做競品分析。
我的產品目標是：[一句話描述目標]
目標使用者是：[描述族群與使用情境]
核心任務是：[使用者最重要要完成的任務]

請幫我設計一份競品分析表，包含：
1. 競品選擇欄位。
2. UX/UI 分析維度。
3. 功能與內容分析維度。
4. 商業策略分析維度。
5. 可收斂成設計機會的欄位。

每個欄位請附上觀察問題，讓初學者知道要看什麼。
```

### 二、整理競品觀察成洞察

```text
以下是我整理的競品分析表內容：
[貼上表格或重點]

請協助我整理：
1. 3 個市場共通模式。
2. 3 個使用者可能遇到的痛點。
3. 3 個設計差異化機會。
4. 每個洞察對應的證據來源。

限制：只能根據我提供的資料歸納，不要自行編造不存在的競品資訊。
```

### 三、從競品觀察產生 Persona 假設

```text
以下是我的競品分析洞察：
[貼上洞察]

請根據這些洞察，產出 1–2 位 Persona 假設，每位包含：
1. 角色名稱與一句話描述。
2. Goals：他想完成什麼。
3. Mental Model：他如何理解這個任務。
4. Context：他通常在什麼情境下使用。
5. Pains：他最容易卡住或不滿的地方。
6. Gains：什麼會讓他覺得有價值。
7. 需要後續訪談或測試驗證的假設清單。

請避免只寫年齡、職業、個性等表面資料。
```
