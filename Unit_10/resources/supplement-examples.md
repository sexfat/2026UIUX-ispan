| 可補強內容 | 現有教材依據 | 補強原因 | 補充形式 |
| :--- | :--- | :--- | :--- |

## 補充練習題

### 練習 A：找出 Mockup 精度問題

一張故意有問題的商品列表頁，8 分鐘內只找問題、不改圖。

內含問題：

- 間距：卡片內距 17、列表間距 13、版心左右不一致。
- 狀態：主要按鈕缺 hover / disabled / loading，輸入框缺 focus / error。
- 真實內容：商品名太長會推擠價格；價格欄位遇到 `$128,000` 會太窄。
- 易用性：送出後沒有處理中狀態；錯誤訊息只有「發生錯誤」；目前篩選條件不可見。

### 練習 B：把問題改成可交付版本

20 分鐘內只處理三類高優先問題：

1. 間距回到 8pt 階梯，並有版心、卡片內距、列表間距標註。
2. Button / Input 具備最低狀態集合，並整理到元件區。
3. 錯誤訊息符合「哪裡錯 + 怎麼改」，並具備 loading / disabled 狀態。

### 練習 C：寫可執行的檢查紀錄

反例：

| 不可用寫法 | 問題 |
| :--- | :--- |
| 第 9 條有問題 | 沒有位置，不能改 |
| 這裡怪怪的 | 沒有對應原則 |
| 按鈕不好看 | 是品味，不是使用性問題 |

可用寫法：

| 可用寫法 | 對應改法 |
| :--- | :--- |
| 第 1 條，商品列表套用篩選後沒有 loading 或目前篩選標籤，使用者不知道篩選有沒有生效 | skeleton/loading，以及列表上方的「尺寸 M、價格 $1,000 以下」篩選標籤 |
| 第 5 條，刪除收藏沒有二次確認，手滑會直接刪掉 | 刪除前確認 dialog，或可復原的 snackbar |
| 第 9 條，付款失敗只寫「交易失敗 E-402」，使用者不知道要改哪裡 | 「卡號格式不正確，卡號需為 16 碼」與卡號欄位 focus |

## Figma 練習檔內容

已另外建立 Figma 補充練習檔，使用順序如下：

1. `01 Before：找問題` frame 作為問題觀察材料。
2. 旁邊的便利貼區紀錄至少 5 個問題。
3. `02 After：改稿參考` 作為修正方向參考，不作為視覺風格標準答案。
4. `03 Components：狀態最低集合` 用來檢查 Button / Input variants 是否齊全。
5. `04 Checklist：檢查紀錄模板` 對應作業 8 的檢查紀錄。

## 練習說明

這份補充練習不是新頁面製作，而是辨識「看起來完成，但工程師還不能接」的地方。練習重點是間距、狀態、真實內容與十條易用性原則的問題辨識，再回到專題頁面完成修正。Figma 練習檔裡的視覺風格不是標準答案；標準答案是間距有量測、狀態有 variants、內容撐得住、檢查紀錄能讓下一個人照著改。
