# 內容正確性：每次都要查的那幾條

寫教材時最危險的不是不會，是**把一個大致對的說法寫成絕對句**。學生會照抄，錯的會傳下去。

## 通則

- **不要把「常用於」寫成「就是」。** 一個方法通常有主要用途與次要用途，只寫主要用途、再加一句「不是用來 X」，就把次要用途講死了。
- **不要把某個東西的一個面向當成它的定義。** 尤其是同時有台前與幕後兩面的概念。
- **破除迷思時不要製造新迷思。** 「三次點擊是假的」不等於「點擊次數不重要」。
- **原則有順序時，要講清楚順序。** 四個原則並列，但最後一個要在前三個滿足後才追求——漏掉這句，學生會拿最後一個去砍前三個。
- **指標的判讀不要只給單一結論。** 「A 低 B 高 = 某某有問題」通常只是可能性之一。

## 已知會寫錯的具體項目

這些在 Unit 05 實際發生過，寫到相關主題時逐條核對：

| 主題 | 錯的寫法 | 對的寫法 |
| :--- | :--- | :--- |
| IA 三個關鍵模型 | 把 Sitemap 算成三模型之一 | 三模型是底層 IA 結構／分類法 Taxonomy／導覽 Navigation。Sitemap 是把底層結構畫出來的一份文件，不在三模型內 |
| 卡片分類法 | 「是發想方法，不是驗證方案」 | 最常用在發想階段；封閉式與混合式可用來評估既有或草案分類 |
| 分類法 Taxonomy | 「後台的 metadata 規則」 | 類別、標籤、屬性、受控詞彙、facet 的一整套規則。有幕後（metadata）也有台前（篩選器、標籤列） |
| 連結標籤 4 個 S | 「連結沒有字數上限」 | 沒有固定上限，但「需要多長就多長，不能再更長」。Succinct 排最後，是在滿足前三個之後才追求 |
| 樹狀測試指標 | 「直接率低＝第一層命名有問題」 | 代表使用者繞路。要回看錯誤路徑與折返層級，問題可能出在任一層 |
| 可尋性 vs 可發現性 | 混為一談，都用搜尋解 | 可尋性＝知道要什麼但找不到；可發現性＝不知道存在。後者加搜尋框無效 |

## 交給 Codex 審查的提示詞骨架

```
你是資深 UX 課程設計顧問兼技術審稿。請實際讀檔做審查，不要臆測。

【要審查的檔案】
- Unit_XX/slides.html
- Unit_XX/article.html
- Unit_XX/exercises.html

【來源資料】教材必須忠於這些
- Unit_XX/resources/...

【架構基準】新檔案應與這些一致
- <最新單元>/slides.html
- Unit_03/article.html、Unit_03/exercises.html

【已驗證，不用再查】
HTML 結構、重複 id、內部連結與錨點、未定義 CSS class、投影片張數。

【請聚焦回報，分成五段】
A. 內容錯誤：與來源不符或講錯的觀念，指出檔案與行號。特別查是否把「常用於」寫成「就是」、
   是否把單一面向當成完整定義、破除迷思時是否製造新迷思、有順序的原則是否漏講順序。
B. 來源涵蓋落差：來源資料有列、但教材完全沒提且對本單元有價值的觀念，排優先序，
   說明該放簡報還是講義。
C. 教學設計問題：時間分配是否可行（各段加總是否等於課程總長）、步驟能否實際執行、
   作業是否確實依指定框架、評分是否可操作。
D. 架構一致性偏離。
E. 可刪減：冗餘或對課程長度而言過多的內容。

務必區分「確定的錯誤」與「建議」。用繁體中文回報。
```

Codex 回報後：**A、C、D 的確定錯誤自己修；B 的補充依建議加進講義；E 的刪減要問用戶**。
