# 語調：像老師在講課

目標讀者是**沒有相關背景的學生**。他們不是來讀文件的，是來聽你講的。

## 原則

1. **口語，但不隨便。** 該有的專業判斷不能少，只是講法要像人話。
2. **具體優先於抽象。** 抽象詞讓學生點頭，具體情境才讓學生學會。
3. **例子用學生的生活。** 台灣學生用得到的產品，不要「某知名電商」。
4. **形容詞省著用。** 過度正向的詞（強大、完善、極佳、有效提升）刪掉之後，句子通常更清楚。
5. **不要制式連接詞。** 「首先／其次／此外／最後」整組是 AI 腔的標誌。要編號就用 `<ol>`，行文用一般的接法。
6. **專業不打折。** 術語照用，第一次出現用一句白話解釋。不要為了好懂就把內容講淺。

## 常見的 AI 腔句型與改法

| AI 腔 | 問題 | 改成 |
| :--- | :--- | :--- |
| 這帶出一個重要的實務含意 | 空轉一句才進正題 | 直接講那個含意 |
| 值得注意的是，我們需要考量… | 廢話開場 | 刪掉開場，留下要考量的東西 |
| 良好的資訊架構能有效提升使用者體驗 | 全抽象，學生記不住 | 好的 IA 讓使用者不用記住太多東西，也知道下一步要點哪裡 |
| 綜上所述，本節探討了… | 論文腔的總結 | 不需要總結就別寫；要收尾就講「所以你回去要做的是…」 |
| 首先…其次…此外…最後… | 制式結構 | 用 `<ol class="steps">`，或直接一段講完 |
| 透過本單元的學習，學生將能夠… | 教案腔，不是講課 | 「這堂課結束後，你手上會有一張可以拿去畫 Wireframe 的 IA 圖」 |
| 該功能具備高度的擴展性與靈活性 | 形容詞堆疊 | 講清楚擴展什麼、怎麼加 |

## 改寫實例

這些都是實際教材裡的句子。左邊是初稿的寫法，右邊是改過的。

**抽象 → 具體**

> ✗ 資訊架構能有效提升產品的可用性與使用者滿意度。
>
> ✓ IA 沒有先確定，Wireframe 就會一直改：因為每次改導覽、改分類、改頁面關係，畫面都要重畫一次。

**術語沒解釋 → 一句白話帶過**

> ✗ 資訊氣味（Information Scent）是使用者在資訊覓食行為中的關鍵判準。
>
> ✓ 使用者不會讀完整頁再決定，而是像動物覓食一樣「順著氣味走」——從連結文字判斷點下去會不會離目標更近。

**教條 → 講出後果**

> ✗ 應避免使用模糊的連結標籤。
>
> ✓ ✕「了解更多」 ✓「查看退款條件」。前者使用者不知道點下去會看到什麼，只好先點點看，錯了再退回來。

**制式結構 → 直接講**

> ✗ 首先進行卡片準備，其次招募參與者，此外需注意分類活動的執行方式，最後進行結果分析。
>
> ✓ 一張卡片一個功能，用使用者看得懂的詞。找目標使用者，不是找同組同學。分的時候不要解釋卡片意思——參與者理解錯了，本身就是發現。

**空泛提醒 → 具體到可執行**

> ✗ 分析時應保持客觀，避免主觀臆測。
>
> ✓ 分群結果只是表面，「為什麼這樣分」才是能拿來設計的東西。記錄的時候抄原句，不要抄你的摘要。

**條列沒有溫度 → 講出學生會踩的坑**

> ✗ 常見錯誤：分類名稱不清楚。
>
> ✓ 分類彼此語意重疊（「服務」「解決方案」「產品」），使用者無法判斷差別。

## 三份檔案的語調差異

同一套原則，力道不一樣：

- **簡報**：最口語。一張投影片一個重點，句子短，敢用「這個最常錯」「先別急著畫」這種話。標題可以用問句（「研究做完了，然後呢？」）。
- **講義**：可以長一點、完整一點，但仍然是講稿的展開版，不是論文。段落之間用因果與情境連接，不要用「本節將探討」。
- **練習與作業**：像在旁邊指導。用祈使句直接下指令（「去找隔壁組借 1 個人」），並說明為什麼要這樣做（「組內成員已經看過整個討論過程，測不出東西」）。

## 自我檢查

寫完之後隨機挑三段唸出來。判斷標準只有一個：**像人在講話，還是像在念稿。**

念起來卡住的地方，通常是這幾種：一句話塞了兩個以上的抽象名詞、連接詞是「此外」、或者整段講完學生還是不知道要做什麼。
