單元教材是三份互相串接的 HTML，加上 README 與首頁入口。做出來容易，做對很難——難的部分永遠是同樣五件事：**講課**、**溯源**、**對標**、**對帳**、**驗收**。

## 講課：用講給學生聽的口氣寫

教材是講稿，不是文件。寫每一句之前，先問自己「這句話我會在教室裡講出來嗎」——不會，就重寫。

- **口語但不隨便。** 像老師站在台前講給你聽，不是企業簡報、不是學術論文、更不是 AI 生出來的那種文章。
- **具體換掉抽象。** 不要「提升使用者體驗」，要「使用者不用退回上一頁重找」。抽象詞學生點頭但學不會。
- **舉學生生活裡的例子。** 蝦皮、外送、選課系統、健保快易通——比「某電商平台」有用得多。
- **少用過度正向的形容詞。** 「強大」「完善」「有效提升」這類詞刪掉，句子通常更清楚。
- **不要每段都「首先、其次、此外、最後」。** 該用序號的地方用 `ol`，行文就用一般的連接方式。
- **專業不能砍。** 術語照用，但第一次出現要用一句白話解釋，不要因為要好懂就把內容講淺。

**完成條件：** 隨機挑三段唸出來，聽起來像人在講話，不像在念稿。

改寫的實例與常見的 AI 腔句型見 [references/tone.md](references/tone.md)。

## 溯源：每一句都指得出來源

`Unit_XX/resources/` 裡的檔案是這個單元的唯一內容依據。教材裡的每個觀念、每張表、每組數字，都要能指回來源檔案的哪一段。

- 來源沒說的，不要寫。要補充就先查證，並在 `.refs` 標出出處。
- 來源資料本身不要改，也不要「順手整理」。
- 課堂練習的素材（卡片、案例、情境）優先直接取用來源資料裡現成的，不要另編一套。
- 影片、Figma board 這類連結是教材的一部分，要嵌進簡報與練習頁，不是只列在參考資料。

**完成條件：** 教材中的每個小節，你都答得出「這來自 resources 的哪一份、哪一段」。答不出來的段落，刪掉或補來源。

## 對標：版型抄最新的單元

不要自創版型。動手前先讀完當前最新單元的對應檔案，把 CSS 與 JS 整段沿用：

| 你要做的 | 抄誰 |
| :--- | :--- |
| `slides.html` | 最新一個做完的單元簡報 |
| `article.html` | `Unit_03/article.html` |
| `exercises.html` | `Unit_03/exercises.html` |

新元件可以加，但**加了淺色樣式就要補深色樣式**——`.slide.dark` 底下少一條，那張深色頁就會出現看不見的文字。

細節契約（色票、必備 class、JS 行為、行內連結）見 [references/design-system.md](references/design-system.md)。

**完成條件：** 新檔案的 `:root` 色票與參照單元完全一致，且每個新增 class 都有對應的 `.slide.dark` 規則。

## 對帳：同一個數字要對三次

這是最容易錯、也最難自己看出來的一項。**同一個事實一旦寫在兩個地方，就一定要對帳。**

必對的三組：

1. **時間**。單元總長由 `index.html` 的時段決定。簡報 Agenda 的各 Part 加總必須等於總長；課堂練習的各階段加總必須等於簡報寫的實作時間；分享、休息也要算進去。這三個數字散在 `slides.html`、`exercises.html`、`README.md`，改一處就要改三處。
2. **張數與節數**。簡報封面 `cover-meta` 寫的「NN 張投影片」要等於實際 `.slide` 數量；`README.md` 寫的講義節數要等於實際 `sec-num` 數量。
3. **交叉引用**。講義插入或刪除小節後，`sec-num` 全部重編，於是 `#sN` 錨點、側邊大綱、TOC、以及其他檔案裡的「講義第 N 節」全部會歪。重編號一定要連同這四處一起改。

**完成條件：** 上述每個數字，你都在所有出現的檔案裡確認過一次。

## 驗收：跑腳本，紅了不算完成

```bash
python3 .claude/skills/unit-materials/validate.py Unit_XX
```

它會檢查 HTML 結構、重複 id、內部連結、跨檔錨點、未定義的 CSS class、簡報張數與封面標示是否相符、講義節號是否連續、以及「第 N 節」的交叉引用是否指對。它還會把所有時間數字列出來讓你對帳——這一項腳本不會判對錯，要你自己看。

**完成條件：** 腳本全綠，且時間報表加總正確。

## 內容正確性：交給 Codex 對照來源審一次

自己寫的教材，自己看不出觀念講錯。三份檔案寫完後跑一次：

```bash
codex exec --skip-git-repo-check "<把 references/content-traps.md 的檢查清單貼進來，附上檔案路徑與來源路徑>"
```

Codex 回報後，**確定的錯誤自己修，刪減建議要問用戶**——刪的是他的教材，不是你的。

UX 觀念的常見錯法（每次都要查的那幾條）見 [references/content-traps.md](references/content-traps.md)。

## 練習與作業：要能改得動

課堂練習與回家作業不是把觀念再講一次，是要學生動手。每份都要有：

- **時間與分組**寫死（幾分鐘、幾人一組、誰當參與者）。「找同學」不夠，要寫「去隔壁組借 1 人，因為組內成員已經看過討論過程」。
- **交件清單**：具體到可勾選。
- **配分**：100 分配比，每項附「不及格的樣子」——沒有反例，評分尺度會飄。
- **AI 使用界線**：哪些可以給 AI 做、哪些不行，寫清楚為什麼。

## Figma 板：要建就建成可直接上課的

需要學生在 Figma 上操作時，把素材預先建好，不要只給空白連結。

呼叫 `use_figma` 前**必須**先載入 figma-use skill。Codex 在 headless 模式寫不了 Figma，板子要由這邊建。

FigJam 的座標與 API 陷阱見 [references/figma-board.md](references/figma-board.md)。

## 收尾

1. `index.html` 的該單元卡片換掉「簡報準備中」，加上三個入口。
2. `README.md` 補相關檔案、時間分配、練習、作業、參考資料。
3. 修改既有文件前先列變動清單問過用戶——規則見專案根目錄 `CLAUDE.md`。
4. 跑 `/maintain-log` 記錄。
