## 單元目標

- 理解用戶旅程地圖如何描述使用者在時間序列中的行動、情緒與接觸點。
- 能辨識旅程中的峰值體驗、甜點、痛點與服務缺口。
- 能把研究觀察收斂成明確的設計目標與改善機會。
- 能在 Figma 中完成一份可用於專題決策的旅程地圖。

## 課程介紹

Persona 幫助我們定義「誰在使用」，用戶旅程地圖則進一步描述「他如何完成一件事」。這個單元會把使用者從產生需求、尋找資訊、採取行動到完成任務的過程攤開，找出每個階段的情緒起伏與阻力。

旅程地圖的重點不只是列流程，而是看出體驗中的峰值與落差。甜點代表可以被強化的正向時刻，痛點代表阻礙任務完成或造成焦慮的節點；兩者都會影響後續功能優先順序與介面設計目標。

完成旅程地圖後，設計目標會從抽象方向變成可執行句子，例如降低等待焦慮、縮短比較時間、讓新手更容易確認下一步。這些目標會成為資訊架構、Flowchart 與 Wireframe 的判斷依據。

## 課程內容

- 用戶旅程地圖結構：階段、行為、想法、情緒、接觸點與機會。
- 峰值體驗：使用者最有感的正向或負向時刻。
- 甜點與痛點：強化價值、降低阻力、找出介面改善優先順序。
- 從旅程問題到設計目標：將觀察轉成可檢核的設計方向。
- Figma 旅程地圖製作：欄位規劃、情緒曲線、標註與討論版本管理。

- Journey Map 的定義、用途，以及與 Persona、User Flow 的差異。

- 教學示意案例：第一次報名 UI/UX 轉職課程。
- 參考案例：牙醫預約體驗，從顧客旅程延伸至 Feature Breakdown。
- Current-state／Future-state、Breadth × Depth 與空白實作骨架。
- 訪談資料轉旅程地圖的五步示範：讀原話、拆證據卡、排時間、填層次、收斂洞察。

- 獨立互動練習頁：寵物美容、共享汽車、機場接送、網購退貨退款，皆包含人物誌、未分類的故事式模擬訪談、AI 分析提示、可編輯 Journey Map 與情緒曲線。
- 從證據、模式與原因收斂洞察，再轉成設計目標與優先順序。
- AI 協作守則、課堂實作流程與作業規格。
