*Codex 審查與修正*
以 `codex exec` 對三份檔案做內容審查，修正 11 項確定錯誤：

1. 講義第 2 節標題「IA、導覽與 Sitemap：三個關鍵模型」會讓 Sitemap 被誤認為三模型之一 → 標題改為「IA、導覽與 Sitemap 的差異」，並在三模型段落明講 Sitemap 不在其中。
2. 「卡片分類法不是驗證你的方案」過度絕對，封閉式卡片分類本就是評估既有分類 → 改為「最常用在發想階段，封閉式／混合式可用來評估分類草案」。
3. Taxonomy 定義為「後台 metadata 規則」太窄 → 三處改為包含類別、標籤、屬性、受控詞彙與 facet，並點明有台前（篩選器）與幕後（metadata）兩面。
4. 「連結沒有字數上限」語氣過頭 → 補上 NN/g 原則「需要多長就多長，但不能再更長」。
5. 樹狀測試「直接率低＝第一層命名有問題」推論太單一 → 改為需回看錯誤路徑與折返層級，問題可能出在任一層。
6. **時間對不上**：簡報 Agenda 寫 Part 3 為 75 分，練習頁與 README 寫 90 分，加總 195 分超過 180 分 → 重排為 55 / 30 / 95（實作 80 + 分享 15），練習四階段改為 15/25/18/22。
7. 各組 3 分鐘成果分享未計入時間 → 獨立為 15 分鐘時段，三份文件同步。
8. 封閉式分類的參與者未寫死 → 明訂「去隔壁組借 1 人」並說明為何不能用組內成員。
9. 回家作業「畫使用者看得到的結構」會與底層 IA 混淆 → 改為先畫觀察得到的、再用另一色標推測的底層結構，兩者必須分開。
10. 評分重點缺權重 → 加上 100 分配比與「不及格的樣子」對照欄。
11. 簡報資源連結未開新分頁（與 Unit_04 不一致）、講義參考資料寫錯來源檔名 → 皆修正。

**已知問題 / 備註：**
- Codex 的 `use_figma` 在 headless 的 `codex exec` 模式下需要互動核准，兩次寫入（含最小測試腳本）皆回傳 `user cancelled MCP tool call`。最終由 Codex 建立空白檔案，內容改由 Claude Code 端的 Figma MCP 補完。
- FigJam 的 `SectionNode` 子節點使用**相對於 section 的座標**而非絕對座標。第一批卡片因此落到隔壁區，已重新定位（`n.x -= section.x`）。後續若要再擴充板子，須注意此行為。
- FigJam `TableNode` 沒有 `resize`／`resizeWithoutConstraints`，無法用程式調整表格寬度，兩張表維持預設寬度，需手動拉寬。
- Codex 建議 26 張投影片對 85 分鐘講述時間偏多，可將常見 IA 錯誤、卡片分類常見錯誤、內容模型、4 個 S 移至講義。經確認後決定維持 26 張不動。
