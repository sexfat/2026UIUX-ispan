# 單元 6：十大易用性原則與檢查表實務

## 單元目標

- 理解 Jakob Nielsen 提出的十大易用性原則（10 Usability Heuristics）的內容與意涵。
- 能夠用十大原則對現有介面進行系統性的 UX 審查。
- 學會撰寫簡易的易用性檢查報告，標記問題並提出改善建議。
- 建立以使用者為中心的設計評估習慣。

## 課程介紹

本單元介紹 UX 領域最經典的評估框架——Nielsen 十大易用性原則。這套原則涵蓋系統狀態的可見性、錯誤預防、一致性、彈性效率等面向，是設計師在審查介面時最常用的參考依據。

課程將逐一說明每條原則的意涵，並搭配真實 App 與網站的案例進行分析，讓學員能夠直觀地理解原則在實際介面中的體現。課堂也將帶領學員實際操作一份易用性檢查表，針對指定介面進行評估練習。

課程結束後，學員將能獨立使用十大易用性原則審查一個介面，並產出有具體依據的 UX 改善建議。

## 課程大綱：讓設計更符合直覺

### 1. 系統狀態的可見性 (Visibility of System Status)

* **核心概念：** 系統應在合理的時間內，透過適當的回饋讓使用者了解目前的狀況。
* **教學點：** 進度條、讀取動畫、點擊後的按鈕樣式變化（Loading state）。
* **檢查項：**
* [ ] 使用者是否知道目前所在的頁面或步驟？
* [ ] 執行動作後，是否有明確的視覺或聽覺回饋？



### 2. 系統與真實世界的連結 (Match Between System and the Real World)

* **核心概念：** 使用使用者熟悉的語言、詞彙與概念，而非系統導向的專門術語。
* **教學點：** 圖示語義（如：垃圾桶代表刪除）、擬物化邏輯的延續。
* **檢查項：**
* [ ] 文字標籤是否使用了目標族群慣用的術語？
* [ ] 圖示的隱喻是否符合大眾的認知？



### 3. 使用者的控制權與自由 (User Control and Freedom)

* **核心概念：** 使用者常會誤觸或做出錯誤決定，系統需提供明顯的「緊急出口」。
* **教學點：** 復原（Undo）、重做（Redo）、取消按鈕、返回上一頁。
* **檢查項：**
* [ ] 是否有清楚的「取消」或「關閉」機制？
* [ ] 流程中是否允許使用者隨時返回上一步？



### 4. 一致性與標準 (Consistency and Standards)

* **核心概念：** 使用者不應懷疑不同的詞彙、情境或動作是否代表同一件事。遵循平台規範（iOS HIG / Material Design）。
* **教學點：** Design System 的重要性、全站組件的一致化。
* **檢查項：**
* [ ] 相同的動作（如：儲存）在不同頁面的位置與顏色是否一致？
* [ ] 是否遵循了通用的作業系統設計規範？



### 5. 錯誤預防 (Error Prevention)

* **核心概念：** 比起精美的錯誤訊息，更好的設計是「防止錯誤發生」。
* **教學點：** 輸入框的格式限制（如：日期選擇器）、刪除前的二次確認。
* **檢查項：**
* [ ] 是否在執行高風險動作（如：刪除帳號）前提供確認提示？
* [ ] 是否透過限制輸入格式來減少使用者犯錯的機率？



### 6. 辨識而非記憶 (Recognition Rather Than Recall)

* **核心概念：** 減少使用者的記憶負荷，將物件、動作與選項可視化。
* **教學點：** 最近搜尋紀錄、麵包屑導航（Breadcrumbs）、工具提示（Tooltips）。
* **檢查項：**
* [ ] 使用者是否需要記住前一個頁面的資訊才能完成目前的動作？
* [ ] 所有的功能說明是否在需要時能輕易取得？



### 7. 使用的彈性與效率 (Flexibility and Efficiency of Use)

* **核心概念：** 系統應兼顧新手與專家。為專家提供快捷鍵或自動化設定。
* **教學點：** 快捷鍵、自定義面板、常用功能捷徑。
* **檢查項：**
* [ ] 是否有提供進階使用者使用的快捷操作？
* [ ] 系統是否能記憶使用者的偏好以提升效率？



### 8. 極簡主義與美學設計 (Aesthetic and Minimalist Design)

* **核心概念：** 對話框不應包含無關或很少用到的資訊。
* **教學點：** 資訊層級（Information Hierarchy）、留白的力量、減少視覺雜訊。
* **檢查項：**
* [ ] 頁面上的元素是否都具備必要的功能？
* [ ] 視覺設計是否有效地引導使用者的注意力到核心任務上？



### 9. 協助使用者辨識、診斷並從錯誤中復原 (Help Users Recognize, Diagnose, and Recover from Errors)

* **核心概念：** 錯誤訊息應以純文字敘述，準確指出問題並提供解決方案。
* **教學點：** 404 頁面的引導、表單驗證錯誤的具體提示（而非僅顯示「輸入錯誤」）。
* **檢查項：**
* [ ] 錯誤訊息是否避開了生硬的錯誤代碼（如：Error 0x804）？
* [ ] 訊息是否有給出明確的下一步解決建議？



### 10. 協助與說明文件 (Help and Documentation)

* **核心概念：** 雖然最好不需說明就能使用，但仍應提供易於搜尋且專注於任務的說明。
* **教學點：** 常見問題（FAQ）、新手引導教學（Onboarding）、上下文說明的搜尋功能。
* **檢查項：**
* [ ] 說明文件是否容易找到且易於搜尋？
* [ ] 教學內容是否以使用者的任務為導向進行編排？

## 易用性檢查表 (Usability Checklist) 小卡範本

| 原則項目 | 關鍵自問自答 | 狀態 (V/X) |
| --- | --- | --- |
| **1. 系統狀態** | 我現在在哪？剛才的操作成功了嗎？ |  |
| **2. 現實連結** | 這個圖示或文字，我阿嬤看得懂嗎？ |  |
| **3. 控制自由** | 我能隨時反悔並點擊「取消」嗎？ |  |
| **4. 一致性** | 這裡的「確定」跟那裡的「OK」是同一件事嗎？ |  |
| **5. 錯誤預防** | 系統有幫我擋掉可能填錯的格式嗎？ |  |
| **6. 辨識記憶** | 我不用背下產品代碼也能找到我要的東西嗎？ |  |
| **7. 彈性效率** | 熟客可以用更快的速度完成結帳嗎？ |  |
| **8. 極簡美學** | 畫面上有沒有干擾我完成任務的贅語？ |  |
| **9. 錯誤復原** | 壞掉的時候，系統有告訴我該怎麼修嗎？ |  |
| **10. 說明文件** | 當我真的卡住時，有人能幫我嗎？ |  |



範例：
在 UI/UX 教學或工作坊中，使用知名產品的真實介面作為範例，最能讓學員瞬間理解「原則如何落地」。以下為你整理知名網站與應用的 UI 實際範例，並附上核心原則的視覺對應焦點：

---

### 原則 1：系統狀態的可見性 (Visibility of System Status)

* **真實範例：** **蝦皮購物 (Shopee) / 淘寶** 的物流追蹤頁面、**Uber** 的地圖車輛動態。
* **UI 表現：** 透過進度條（Steppers）將「訂單處理中、已出貨、運送中、已送達」數位化，並用高亮色彩標示當前節點。

---

### 原則 2：系統與真實世界的連結 (Match Between System and the Real World)

* **真實範例：** **Apple iBooks** 早期的木紋書架（擬物化），或是當前各大電商的「購物車 (Shopping Cart)」圖示。
* **UI 表現：** 介面不使用 `Save to Database_v2`，而是用「加入購物車」與「垃圾桶」圖示。這延續了使用者在實體超市推推車、將不要的物品丟進垃圾桶的真實生活經驗。

---

### 原則 3：使用者的控制權與自由 (User Control and Freedom)

* **真實範例：** **Gmail** 寄出信件後的「復原 (Undo)」彈出視窗、**Mac Trash** 的「放回原處」。
* **UI 表現：** 當使用者誤刪資料或點錯按鈕時，系統在底部提供一個停留 5-7 秒的 Snackbar 提示，允許使用者一鍵「撤銷操作」，提供安全的避難出口。

---

### 原則 4：一致性與標準 (Consistency and Standards)

* **真實範例：** **Google 全系列產品**（雲端硬碟、日曆、Keep）右上角的九宮格與個人頭像配置。
* **UI 表現：** 遵循 **Jakob's Law（雅各布定律）**：使用者大多的時間都在別的網站上，因此他們期望你的網站運作方式與其他熟知的網站相同。例如電商網站的「搜尋框」一定在頂部中央或偏左，「購物車」一定在右上角。

---

### 原則 5：錯誤預防 (Error Prevention)

* **真實範例：** **Google 搜尋** 的「您是不是要查...（Did you mean）」、**GitHub** 刪除儲存庫時要求輸入完整專案名稱。
* **UI 表現：** 在密碼設定輸入框中，直接在下方列出規則（如：需含大寫字母、數字），並在使用者邊輸入時邊將符合的條件轉為綠色勾勾，在「送出表單前」就引導正確輸入，防止點擊後才跳出錯誤。

---

### 原則 6：辨識而非記憶 (Recognition Rather Than Recall)

* **真實範例：** **Netflix / YouTube**首頁的「繼續觀看」區塊、**Canva** 的「最近使用過的字體/圖形」。
* **UI 表現：** 系統主動幫使用者記住資訊。使用者不需要在腦中回想「我上週看到哪一集？」或「我上次用哪種藍色？」，介面直接視覺化呈現歷史紀錄供點擊。

---

### 原則 7：使用的彈性與效率 (Flexibility and Efficiency of Use)

* **真實範例：** **Figma / Photoshop** 的快捷鍵系統、**macOS** 的「接續互通 (Continuity)」與自動填入驗證碼。
* **UI 表現：** 新手可以點擊圖層菜單複製（點擊 3 次），老手直接用 `Cmd + D`（點擊 1 次）。系統為不同熟練度的使用者提供多元的任務達成路徑（Accelerators）。

---

### 原則 8：極簡主義與美學設計 (Aesthetic and Minimalist Design)

* **真實範例：** **Google 首頁**（極致的留白與單一搜尋功能）、**Apple 產品官網**。
* **UI 表現：** 畫面中不出現「當下任務不需要」的雜訊。強大的**資訊層級 (Visual Hierarchy)** 讓主要行動按鈕 (CTA) 凸顯，次要資訊淡化或隱藏在下拉選單中。

---

### 原則 9：協助使用者辨識、診斷並從錯誤中復原 (Help Users Recognize, Diagnose, and Recover from Errors)

* **真實範例：** **Airbnb** 註冊時手機號碼少打一碼，輸入框變紅並提示「手機號碼格式不正確，請檢查是否有漏字」。
* **UI 表現：** 絕對不使用內部工程師才懂的 `Error Code: 400 Bad Request`。好的 UI 會用純文字告訴使用者：「系統偵測到此 Email 已被註冊，您可以[點此找回密碼]」，直接給予對應的救援方案。

---

### 原則 10：協助與說明文件 (Help and Documentation)

* **真實範例：** **Notion** 介面右下角的 `?` 幫助圖示、**Slack** 的新手引導機器人 (Slackbot)。
* **UI 表現：** 說明文件不是厚厚一本 PDF。而是在使用者觸及新功能時， UI 彈出適時的 Tooltip（氣泡提示）進行上下文引導（Contextual Help），或是隨時可搜尋的 FAQ 常見問題面板。

---

### 教學應用建議

在工作坊中，你可以隨機挑選一個「本土知名政府報稅網站」**或**「傳統銀行系統」作為反面教材（通常能找到許多違反原則 4, 5, 8 的地方），再對比上述 **Apple、Google、Netflix** 等正面案例，學員的吸收效果會非常顯著。
