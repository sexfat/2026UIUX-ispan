# 單元 2：使用者訪談、訪綱製作與研究方法取向

## 單元目標

- 理解使用者訪談在探索階段（Discovery）的角色，與執行使用者訪談的 6 個步驟與訪談的局限性。
- 能先設定具體研究目標，再據此設計一份結構完整的訪綱（Interview Guide）。
- 學會撰寫開放式、聚焦具體事件的問題，並避開誘導、假設、複合等常見錯誤。
- 懂得如何篩選對的受訪者、判斷該訪幾個人（飽和點），並進行預訪修正。
- 能運用 AI 協助產生訪綱草稿、檢查誘導性問題與模擬受訪者預訪，但保留研究判斷權。
- 能在訪談後用 AI 協助整理逐字稿：萃取痛點、歸納主題、產出使用者需求陳述。
- 能區分質化與量化研究的目的與適用時機，並理解使用者訪談屬於質化、態度型方法。

## 課程介紹

這個單元承接第一堂的設計流程觀念，聚焦在研究的第一步：把「想了解使用者」變成「一場能問出洞察的訪談」。訪談不是聊天，而是一種有研究目標、有結構、有技巧的質性研究方法，它的產出會成為後續 Persona、同理心地圖與使用者旅程的素材。

課程會帶學員從研究目標出發，一步步搭出訪綱的四段結構：暖身破冰、核心情境探索、深入動機探底、收尾致謝。過程中會反覆強調「問過去的真實經驗，而非假設與通則」，並用實例拆解六個最常見的提問錯誤，讓學員寫出的問題真的能引出故事。

AI 在這裡是訪綱的協作者：它可以根據研究目標快速產出問題草稿、檢查問題是否帶有誘導性、甚至扮演受訪者讓學員預演訪談節奏。但要訪誰、訪幾個人、哪些回答值得追問，仍由研究者判斷。

本單元也會把訪談放回更大的研究地圖裡：一邊練「怎麼問」的訪綱技巧，一邊建立「什麼時候該用質化、什麼時候該用量化」的全局觀。質化研究回答「為什麼」、量化研究回答「多少」，使用者訪談只是研究工具箱裡的一種；認清它的位置與限制，才知道何時該搭配問卷、數據或測試來補強。

## 課程內容

- 為什麼做使用者訪談：探索階段的態度型研究，與可用性測試的差異。
- 訪談前第一步：把模糊的好奇心收斂成具體、可被回答的研究目標。
- 篩選受訪者：Screener 問卷、納入／排除標準、聚焦過去行為、排除專業測試員。
- 該訪幾個人：質性研究的飽和點概念、6–12 人的實務參考、滾動式調整。
- 訪綱的四段結構：暖身破冰 → 核心情境探索 → 深入動機探底 → 結尾致謝。
- 好問題的寫法：開放式、引導回憶具體事件、主問題下嵌套追問與探底問句。
- 撰寫訪談問題的 6 個常見錯誤與改善方法。
- 訪談現場技巧：多聽少說、擁抱沉默、建立信賴、中立追問。
- 預訪（Pilot）：用 1–2 人測試訪綱，修正聽不懂或無效的問題。
- AI 協作（訪談前）：依研究目標生成訪綱草稿、檢查誘導性問題、模擬受訪者預演。
- AI 協作（訪談後）：把逐字稿交給 AI 萃取痛點、Affinity 主題分群、整理使用者需求陳述。

研究方法取向（質化／量化）：

- 質化 vs 量化：質化問「為什麼／如何修」，量化問「多少／多嚴重」。
- 樣本數與目的：質化少量（約 5–8 人）做形成性評估；量化大量（30+ 人）做總結性／基準測試。
- 三角驗證（Triangulation）：質化找問題根源、量化驗證影響範圍，互補使用避免單一方法盲點。

## 質化與量化研究

使用者訪談是質化研究的一種，但要判斷它適不適用、需不需要其他方法補強，得先看懂質化與量化的分工。

| 面向 | 質化研究（Qualitative） | 量化研究（Quantitative） |
|------|------------------------|--------------------------|
| 核心問題 | 為什麼？如何修？ | 有多少？多嚴重？ |
| 樣本數 | 少量（約 5–8 人） | 大量（通常 30+ 人） |
| 角色 | 形成性（Formative），引導設計方向 | 總結性（Summative）／基準測試，評估成效 |
| 產出 | 問題清單、痛點、洞察（依嚴重度排序） | 統計指標、顯著性、誤差範圍 |
| 代表方法 | 使用者訪談、可用性測試 | 大樣本問卷、A/B 測試、可用性基準 |

- **質化的限制：** 結果是研究員依經驗解讀的估計值，不同人可能看出不同問題（評估者效應 Evaluator's Effect）；少量樣本也可能無法完全代表整體使用者，結論會有偏差。
- **量化的價值：** 透過足夠樣本與統計，結論不靠運氣（具統計顯著性與誤差範圍），適合說服管理層、追蹤改版前後的成效變化。
- **三角驗證（Triangulation）：** 兩者互補——用質化找出問題根源、用量化驗證問題的影響範圍，避免只靠單一方法產生盲點。
- **本單元定位：** 使用者訪談屬於質化、態度型方法，是探索階段最常用的工具；本單元的訪綱練習，就是把這個工具用好。

## AI 協作提示詞

> 以下提示詞會整理進獨立輔助頁面（規劃中：`Unit_02/interview-prompt.html`，格式對標 `Unit_01/persona-prompt.html`）。所有提示詞皆為學生視角，使用前請替換 `[ ]` 內容；AI 的回覆只是草稿與假設，最終仍由研究者判斷。

### 一、訪談前：生成訪綱草稿

```
你是一位資深的 UX 研究員。我正在為 [產品／主題] 進行探索階段的使用者訪談。
研究目標：
1. [目標一，例如：了解使用者在規劃自助旅行時的主要痛點與動機]
2. [目標二]
目標受訪者：[用「過去行為」描述，例如：過去三個月內曾自行在網路上規劃並完成一趟自助旅行的人]

請幫我產出一份 45–60 分鐘的半結構化訪綱，包含：
1. 開場導言（說明訪談目的、徵求錄音同意、強調沒有標準答案）。
2. 暖身破冰問題 2 題（簡單、不具批判性）。
3. 核心情境探索 3 題：每題引導受訪者回憶「最近一次」的具體經驗，各附 2 個追問。
4. 深入動機探底 3 題：挖掘價值觀與心理模型，各附 1 個探底問句（如「為什麼那對你很重要？」）。
5. 結尾問題與致謝。
全程使用開放式問句，避免誘導性、假設性與複合式問題。
```

### 二、訪談前：檢查問題是否踩雷

```
以下是我寫的訪談問題：
[貼上你的問題清單]

請以 UX 研究員的角度逐題檢查，指出是否犯了下列任一錯誤，並提供中立的改寫版本：
（1）一開場就問封閉式篩選問題（2）只問「通常／典型」行為而非具體事件
（3）假設性／預測未來的問題（4）追問時加入研究員自己的詮釋（誘導）
（5）一次塞多個問題的複合式問題（6）使用「安全」「常」等模糊詞彙。
```

### 三、訪談前：用 AI 模擬受訪者做預訪（Pilot）

```
你現在是一位受訪者：[年齡／職業／情境，例如：32 歲、有兩個小孩、平日很忙的上班族]。
我要對你進行一場使用者訪談的預訪，主題是 [主題]。
請依你的角色設定，真實、簡短地回答我接下來的每一個問題；
如果某個問題你聽不懂、覺得被誘導、或同時問了太多事，請直接告訴我。
準備好後，我會開始提問。
```

### 四、訪談後：用 AI 協作整理資料

```
以下是 [N] 場使用者訪談的逐字稿／筆記（已標註受訪者編號）：
[貼上內容]

請以 UX 研究員的角度協助我整理：
1. 逐位萃取每位受訪者提到的痛點、需求與動機，並標註出自哪一位（P1、P2…）。
2. 將相似的痛點歸納成 3–5 個主題（Affinity 分群），為每個主題命名並一句話說明。
3. 標出哪些主題在多位受訪者間重複出現（高頻訊號），哪些只出現一次。
4. 以「使用者需求陳述（User-need statement）」格式產出 3 條核心洞察。
限制：只根據逐字稿內容歸納，不要加入推測或腦補；若某結論的資料不足，請直接說明。
```
